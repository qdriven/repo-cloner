WHY · 为什么要做这个项目

日常收集外部参考资料，原本被割裂成三条高摩擦链路

每次从浏览器切去终端或顺手塞进书签栏，要么打断阅读心流，要么让资料永远停留在浏览器里吃灰。

痛点 01 · 仓库克隆 6 步 / ~60s

手敲终端，慢网易断

  • 复制 GitHub URL → 切终端 → 翻目录、拼路径
  • 纠结放进 skills 还是 others 子目录
  • 忘了加 --depth=1，大仓拉取漫长占空间
  • 国内网络偶发超时，中断后还得手动清理重敲
痛点 02 · 好文与推文 书签即吃灰

散落浏览器，Agent 不可见

  • 刷到高质量技术推文或博客，收藏进浏览器书签
  • 本地 Cursor / Claude Agent 无法读取书签上下文
  • 缺少备注、来源时间戳与待抓取状态追踪
痛点 03 · 在线工具站 缺少收口

想整站参考，无处登记

  • 看到交互惊艳的在线工具站或文档站想离线复刻
  • 和普通文章混在一起，分不清「读内容」还是「扒整站」
  • 缺少统一的本地站点收藏登记

✂️ 工程与文档减掉了什么？

  • 减掉多处重复逻辑：HTTP 服务、CLI、启停脚本统一收口到同一套本地核心
  • 减掉配置割裂：命令行参数、环境变量 KEEPIT_*、keepit.config.json 合并为一套解析
  • 减掉收集摩擦：安装浓缩为两个脚本，安装与守护一键完成，clone 只需一次点击

🚀 实际使用带来了什么改变？

  • 连刷十几个 GitHub 项目时，连续点选即由后台 5 并发浅克隆自动排队落盘
  • 浏览 X 推文、博客与在线工具站时，无需打断阅读，全部按 collection / clone 分类入库
  • 所有产出的本地路径与 JSON 结构，天然可供工作区内的 AI Agent 直接读取与消费
